## 10. I Built Another Andrej Karpathy Using Claude
- **Link:** https://www.youtube.com/watch?v=bvGptCLDhyo | **Length:** 11 min | **AI-relevant:** yes
- **What it teaches:**
  - A four-step recipe for turning one expert's public thinking into a reusable Claude Code agent. The result is not a voice clone. It copies how the expert reasons and teaches, and it works for any expert (a sales teacher, an author, a coach).
  - Step 1, gather: pull the person's public material (YouTube captions, blogs, GitHub, X posts) with one parallel sub-agent per source. Nate says this yielded 700k+ words in about 45-60 minutes.
  - Step 2, compile: feed the raw folder to an LLM that builds a linked wiki (source pages, topics, principles, methods, an index and a log), following Karpathy's "LLM wiki" idea. Obsidian is optional, just a viewer. Raw files are never edited.
  - Step 3, extract rules: derive a short rule set, each rule tied to an exact quote and its source. Nate's seven rules: build it or you don't understand it; first-order term first; predict, run, then compare; show the broken version first; prove it, don't claim it; state your assumptions; simplicity wins. If a rule has no source, the agent must say it is inferring.
  - Step 4, package and enforce: write the rules into a sub-agent file (separate context window) and a skill (`/karpathy-teach`). Add a Stop-style hook that blocks the agent from finishing a turn if it wrote code but never ran it. Then test on a real task (a byte-pair tokenizer) and as a pre-delivery reviewer ("would the client accept this?").
  - A `/karpathy-ingest <link>` skill adds new sources, updates affected wiki pages, and promotes a one-source "bench" rule to a real rule once it has a second source.
  - Closing idea: you can outsource your thinking but not your understanding.
- **Tools / prices / numbers:**
  - youtube-transcript-api and yt-dlp (free Python packages) for captions.
  - twitterapi.io (paid API): Nate says pulling all of the person's posts since 2023 cost about $1.
  - Claude Code sub-agents, skills and hooks; Obsidian (viewer only); about 6 prompts in total.
- **Skills it demonstrates:** context engineering, LLM-wiki / second-brain knowledge compilation, sub-agent design, Claude Code skills and hooks, verification loops (run-before-answering gates), parallel agent research.
- **Money angle:** A repeatable "expert-in-a-box" build. You could package a client's own founder, coach or SME knowledge into a queryable wiki plus agent and sell it as a custom knowledge-assistant or training bot. The run-before-claiming-done hook is also a quality selling point for client deliverables. No prices stated.
- **Sponsor / affiliate / upsell:** Promotes his free "AI OS kit" and a prompt summary linked in the description (free community resources).

## 11. Master 96% of Codex in under 35 minutes
- **Link:** https://www.youtube.com/watch?v=DFlELTiSPk8 | **Length:** 35 min | **AI-relevant:** yes
- **What it teaches:** 18 core concepts of OpenAI's Codex desktop app, in four groups.
  - Foundations: (1) Projects, meaning a folder of files that Codex treats as persistent context (his "Herc 2" project is his AI operating system). (2) `agents.md`, a plain markdown rules file read before every message, with a routing map telling the agent where business info, voice guides and active projects live. (3) The agent loop: think, use tools, respond, repeat. Watching the visible reasoning teaches you how to prompt it. (4) `/goal`: give an objective and the agent keeps working until done. Objective, checkable goals (e.g. collect N sources then write the report) work best, and he suggests not micromanaging strong models.
  - Migrating from Claude Code: copy `CLAUDE.md` to `agents.md`, copy skills into a `.agents` folder, or just tell Codex to make the project Codex-ready.
  - Workspaces: (5) Local vs cloud. Local means files on your machine (and localhost links only work for you). A phone running the ChatGPT app can remotely drive his desktop Codex while the PC is on. (6) Work trees, a parallel copy of a project for risky changes. He rarely uses them. (7) `.codex` folder, with project-level and user-level (global) settings (config.toml, memories, automations).
  - Control: (8) Model choice per message. (9) Effort levels (low to extra-high, plus "ultra" which needs full access). Higher effort costs more, so match model and effort to the task. "Fast mode" is about 1.5x faster but uses more of the limit. (10) Permissions: full access ("YOLO"), ask-always, or auto-approve-safe. (11) Skills, reusable recipes in `.agents/skills/<name>/SKILL.md` (metadata plus instructions) that you refine through feedback and can invoke as slash commands. Skills can reference other skills, scripts and context files.
  - Tools and scale: (13) Plugins/connectors (Gmail, ClickUp, Google Drive, GitHub, Canva, etc.), with `.env` API keys as the fallback. (14) Built-in browser that can stay logged in to sites such as Skool. (15) Sites: host a page from the app with optional custom domain, analytics and a database, which he says replaces Vercel/Squarespace for simple needs. (16) Sub-agents: the main agent delegates research to cheaper models in parallel. (17) Scheduled tasks that inject a prompt into a Codex session on a schedule, local or cloud. (18) Voice mode that can start threads, delegate and message between threads.
- **Tools / prices / numbers:**
  - Codex desktop app; models named in captions: GPT-6 Astra (strongest, costs the most), smaller tiers (5.6 Soul / Terra as transcribed).
  - API price shown for Astra: $10 per 1M input tokens, $50 per 1M output tokens. Token rule of thumb: about 4 characters, or 3/4 of a word.
  - Subscription tiers mentioned: $20, $100, $200 per month. Extra credits can be bought after the weekly limit (packs such as 2,500 / 5,000 / 25,000).
  - Nate's claim: on the $200 plan, using his full weekly limit equals about $14,000/month of API-priced inference.
  - Demo timings: 25-second agent loop for a summary; he ran 7-8 scheduled trading tasks (see video 17).
- **Skills it demonstrates:** agent harness literacy, context engineering (`agents.md` routing), skill authoring, sub-agent delegation, scheduled/autonomous tasks, model and effort cost control, browser automation, voice-driven orchestration.
- **Money angle:** This is the toolkit for building client automations without n8n: project folders with rules, skills for repeatable deliverables (e.g. content packages), scheduled routines and hosted sites. A service seller could deliver "AI operating system" setups (agents.md plus skills plus connectors) for small businesses. No price points stated for services.

## 12. Claude Code Mods Are Game Changers. Set Up These 5 NOW.
- **Link:** https://www.youtube.com/watch?v=9hetShMMp2s | **Length:** 11 min | **AI-relevant:** yes
- **What it teaches:**
  - "Mods" are a new Claude desktop-app feature. They are small plugins (installed via `/plugin`) that add UI elements or behaviours, and you can create one by describing it in natural language. Official examples shown: a context gauge, a "blast radius" preview of what will be deleted, a replay view of recent diffs, and a "next steps" suggester.
  - Tip: ask Claude to analyse your past session logs and propose the top five mods that would save money, time or keep you organised.
  - His five: (1) Next Steps, three suggested follow-ups after each turn. (2) Cache Keeper, showing the 60-minute prompt-cache window, context size (he showed ~109k tokens), 5-hour and weekly limits and equivalent API cost, with a notification before the cache goes cold and a one-click session-handoff / clear-and-continue button. (3) Recording mode, which blurs or placeholders emails and sensitive data on screen while you record videos. (4) A goal-progress panel for `/goal` runs showing the task list and percent complete across multiple sessions. (5) Collision Guard, which checks before an edit whether another open chat modified the same file in the last 30 minutes and asks you what to do.
  - Distinction he draws: a mod can ask you a question in the UI, whereas a hook just blocks or auto-runs something.
- **Tools / prices / numbers:** Claude desktop app mods via `/plugin`; 60-minute cache expiry; 30-minute file-collision window; 5-hour and weekly usage limits. No prices.
- **Skills it demonstrates:** Claude Code plugins/mods, prompt-cache cost awareness, session handoff, multi-session coordination and guardrails, context management.
- **Money angle:** Mostly productivity. A possible small niche is building custom mods or workflow tweaks for teams, but he states no income angle. Cache-window awareness directly lowers real API spend if you run an always-on agent.
- **Sponsor / affiliate / upsell:** Free SOP for landing a first AI automation client (via his paid community, AIS Plus, which he says hundreds of members used to get first paid jobs; Nate's claim). The mods themselves are offered free via his free Skool community (Classroom > "All YouTube resources").

## 13. How to Actually Build & Sell Software with AI as a Non-Techie
- **Link:** https://www.youtube.com/watch?v=l8ywUsEJ2XQ | **Length:** 70 min | **AI-relevant:** yes
- **What it teaches:** An interview with Dave Ebbelaar (Python developer of 10+ years, building the dictation product "Glido" and an AI agency; the channel shows him as "Dave Ablar").
  - He says he writes no code by hand now; everything goes through Codex or Claude Code. Non-technical and veteran builders now use the same tools; the skill is instructions plus reviewing output. He claims about a 10x speed-up on work he already did, and more on new stacks (his claim).
  - Generalists beat specialists now, because agents outrun handoffs between narrow roles.
  - A four-rung "ladder" of stakes: build for yourself (low risk), internal team tool, sell as a service or productized offer to companies (contracts, data-privacy obligations), consumer software product (privacy law, many users). Do not skip rungs.
  - Spec-driven development and plan mode matter less as models improve. He now describes intent, builds on a branch, and iterates by looking at it ("intent-driven"). Start with a frontier model.
  - Evals: define what good looks like, collect examples (or have a model generate realistic data), then loop "improve against this metric." For subjective outputs use LLM-as-a-judge: have a human label ~100 examples, measure agreement with the judge prompt, and iterate the judge's prompt until alignment is high, re-checking occasionally for drift.
  - Architecture to learn: system level (frontend, backend, database, how they talk) and codebase level (avoid spaghetti from abandoned experiments). He recommends an architecture-review skill from Matt Pocock (named "improve codebase architecture", possibly renamed).
  - Security basics for beginners: use Supabase as default database; enable row-level security; strong passwords and 2FA; keep secrets in environment variables; deploy backends on services like Railway or Render (or a VPS, Azure, AWS, GCP) and firewall/whitelist so only your frontend can reach backend and database.
  - Biggest irreversible risk is a security or data leak.
- **Tools / prices / numbers:** Codex, Claude Code; models named as top frontier: GPT-6 Astra and Opus 5.5; subscriptions $20 to start, likely $100-$200 to avoid running out; Supabase; Railway, Render; Vercel mentioned; Glido targets under 500 ms dictation latency; Matt Pocock's skills. Dave claims his team delivered 50+ AI solutions with Glido (his claim).
- **Skills it demonstrates:** vibe-coding with guardrails, spec vs intent-driven development, evals and LLM-as-judge, system architecture, security hygiene, agency / productized-service positioning.
- **Money angle:** Explicit paths: sell to companies as an AI agency offer (partly productized, partly service, since no automation is identical), or build a subscription software product. Start with personal tools, then internal tools, then paid client work, then consumer product. He says freelance and side-income builders can run agents while working a day job (his view). Customer-support style agents need LLM-judge evals to be trustworthy. No price points.
- **Sponsor / affiliate / upsell:** Mid-roll sponsor segment for CodeRabbit (PR review interface, free 14-day trial per the ad). Plus the AIS Plus first-client SOP (free) and the guest's YouTube channel and "handbook" repo.

## 16. I Tested Sonnet 5.5 vs Opus 5.5. What You Need to Know.
- **Link:** https://www.youtube.com/watch?v=7eo-11K2e3c | **Length:** 26 min | **AI-relevant:** yes
- **What it teaches:**
  - Nate runs the same prompts on Sonnet 5.5 and Opus 5.5 at "high" effort, in parallel, using API-priced costs (not subscription usage) so the dollars are comparable.
  - Rule of thumb he adopts from Anthropic's own guidance: use Sonnet when the task has a clear definition of done and a way to check it (everyday coding, bug fixes, polished docs, slides, spreadsheets). Use Opus for ambiguous, judgment-heavy, long-running agentic work, or when you want a thinking partner to define the goal.
  - Results across 7 tests (scored Sonnet 4, Opus 3 by his count): landing page (Opus nicer overall, Sonnet's hero was striking, Sonnet used a fake generated image; Sonnet won on cost, ~28 min vs ~52 min; Opus ran about twice as long and cost about twice as much; he reckons a re-prompted Sonnet would have cost far less than the ~$13 the pair implied); motion showreel from a branded skill (Opus better: $20.55 vs Sonnet $14.37); vague "90-day plan to 1,000 subscribers" (Opus clearly better, ~$9 vs just under $5); investor deck plus Excel model from fake data (roughly equal, formulas present in both, Opus cheaper and faster here); local-model explainer page (Opus better explanation, Sonnet better visuals); X-scraping news dashboard (Opus slightly better, ~7 minutes longer and ~$6 more); YouTube resource guide using a skill (Sonnet won on cost and speed, near-identical output).
  - Conclusions: with a skill or a specific brief, Sonnet matches Opus at about half the price; with vague prompts Opus's judgment wins. Run each skill on both models and record which is best. Across all tests Opus ran ~46 minutes longer and cost ~$16 more.
  - He also complains when models hard-code spreadsheet values instead of using formulas.
- **Tools / prices / numbers:**
  - Nate says Sonnet 5.5 is 30% faster and 30% cheaper than Sonnet 5 for most tasks.
  - API pricing per 1M tokens: Sonnet 5.5 $2 input / $10 output; Opus 5.5 $4 input / $20 output.
  - Test costs above; example token counts: Sonnet ~20M input / 134K output vs Opus ~37M input / 148K output on the landing page.
  - ElevenLabs-style voiceover mentioned in a generated asset; Gemma 4 and a "32 GB VRAM rule" appeared in a generated local-model explainer.

- **Money angle:** Model routing directly cuts delivery cost on client work: default to Sonnet for well-specified, checkable tasks, escalate to Opus for open-ended strategy. ## 17. I Gave GPT 6 Astra $10,000 to Trade Stocks...And This Happened
- **Link:** https://www.youtube.com/watch?v=eg_1NXDcoPk | **Length:** 18 min | **AI-relevant:** yes
- **What it teaches:**
  - A 7-trading-day experiment: $10,000 of real money, an agent running in Codex with GPT-6 Astra at max settings, success defined as beating the S&P 500. Nate may make up to two strategy changes a day.
  - Architecture: Astra researched and delegated to trading sub-agents, then set up six to seven scheduled "wake-ups" per trading day in one shared thread (pre-market news and watchlist, first-hour entry hunt, midday review, afternoon management, early-close and end-of-day wrap-up). Continuity trick: each run leaves a handoff note for the next so it behaves like one continuous agent.
  - Problems: day 1 was passive (about -$9); Astra later refused to place trades itself (model-level restriction per Nate), so he built a Grok-Bot-style webhook agent called "Trader" with its own email inbox that wakes on an email from Astra and executes orders through Alpaca. Astra remained the strategy/research brain and the bot the executor. He loosened risk filters and wake frequency because the agent was over-cautious, which left ~60% cash by day 3.
  - Result: roughly $9,900 at the end (about -$100, -1%), versus S&P-equivalent of about $9,980 (so it lost the challenge by about 0.8%; Nate's reported figures). A free VIP ticket to his AIS Live event (17-18 October) goes to a community member as the stake. Lesson: seven days is too short to judge; stocks-only gives small moves; he plans longer follow-ups, possibly with options.
- **Tools / prices / numbers:** Codex scheduled tasks, GPT-6 Astra (max effort), Alpaca brokerage API, a Grok-Bot-style agent with email webhook; starting capital $10,000; scheduled sessions at roughly 7:45, 9:30, 11:00, 13:00, 14:15, 14:45, 15:15 (Central); a Fed 25 bp rate rise to 4% mentioned as a market event in the video; 2:1 then 1.5:1 reward-to-risk targets.
- **Skills it demonstrates:** autonomous scheduled agents, multi-agent delegation, handoff-note continuity, email-webhook triggered executor agent, human-in-the-loop strategy tuning, risk-limit tuning, brokerage API integration.
- **Money angle:** None proven; the experiment lost money versus the index. The reusable patterns are the scheduled-wakeup-with-handoff-note design and the "brain agent emails an executor agent" split. Treat as a demo, not an income method; no financial advice implied.

## Batch takeaways
- Highest-value transferable skill: context engineering for agents. Rules file (`agents.md` / `CLAUDE.md`) with a routing map, a skills folder, and a project-per-business structure, so every new chat starts informed (videos 11, 10).
- "Expert-in-a-box" workflow (video 10): gather public material with parallel sub-agents, compile into a linked wiki, extract quote-backed rules, package as sub-agent plus skill plus a verification hook. This can be resold as a custom knowledge or coaching bot for clients.
- Outcome-first selling (video 18) and the ladder of stakes (video 13) give a safe path: personal tools, internal tools, paid client work, then products. Diagnose the real loss (e.g. no-shows) and measure a baseline before building. Read-only first, drafts before sends, human approval for money/deletes, full logs, kill switch.
- Cost control matters for any always-on agent: route work to the cheaper model when the task is well specified and checkable, escalate to the stronger one for vague goals (video 16: Sonnet 5.5 at half Opus's API price). Match effort level to task, and watch the 60-minute prompt-cache window and context size (videos 11, 12, 16). Speed tiers can be a poor bargain (video 14: roughly 4x limit usage for about 2.5x speed on a hard task).
- Evals and LLM-as-judge (video 13) are the way to make subjective agent output trustworthy at scale: human-label about 100 samples, tune the judge prompt until agreement is high, recheck for drift.
- For a future always-on personal bot (Grok Bot / Meta Muse style), video 15 is the design reference: one main chat plus optional side chats; visible, editable soul and memory files; a ~30-minute heartbeat that proactively scans email and docs; approvals tab; schedule tab; WhatsApp/Slack channels; artifacts library; goals/ideas tab; phone access. Video 17 adds two patterns: scheduled wake-ups that pass a handoff note to the next run, and a "brain" agent that triggers a separate executor agent by email webhook.
- Remote-control pattern (video 11): scheduled tasks and phone-to-desktop control let a local machine act like a cloud agent as long as it stays on. Hooks can enforce "run the code before you claim it works" (video 10).
- Treat Nate's trading and earnings-style claims cautiously: the $10k trading test lost money versus the index (video 17), and his community income statements are his own claims.
